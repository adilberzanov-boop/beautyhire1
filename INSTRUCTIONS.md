# BeautyHire — инструкция по запуску

Сайт уже полностью работает как **демо** (откройте `index.html` — можно листать вакансии,
мастеров, фильтры, карточки). Но данные пока не сохраняются. Чтобы сайт стал
«боевым» — с настоящей регистрацией, базой данных и фото — нужно подключить
**Supabase** (бесплатный бэкенд: база данных + авторизация + хранилище файлов).
Это займёт 15–20 минут, писать код не нужно.

---

## Шаг 1. Создать проект в Supabase

1. Зайдите на **supabase.com** → **Start your project** → войдите через GitHub или email.
2. Нажмите **New project**.
3. Укажите название (например `beautyhire`), придумайте пароль от базы данных
   (сохраните его отдельно) и выберите ближайший регион (Frankfurt или Singapore).
4. Нажмите **Create new project** и подождите 1–2 минуты, пока он поднимется.

## Шаг 2. Создать таблицы базы данных

1. В левом меню откройте **SQL Editor** → **New query**.
2. Откройте файл `schema.sql` из этого проекта, скопируйте **весь** его текст.
3. Вставьте в редактор и нажмите **Run**.
4. Если всё прошло без ошибок — в разделе **Table Editor** появятся таблицы:
   `profiles`, `master_profiles`, `salon_profiles`, `vacancies`, `applications`,
   `messages`, `reviews`, `portfolio_photos`.

## Шаг 3. Создать хранилище для фото

1. В левом меню откройте **Storage** → **Create a new bucket**.
2. Название: `avatars`, переключатель **Public bucket** — включить. Создать.
3. Это нужно сделать **до** шага 2 или после — не важно, но если бакет уже был
   создан вручную, повторный `insert` из `schema.sql` просто ничего не сделает
   (это нормально, там стоит `on conflict do nothing`).

## Шаг 4. Получить ключи подключения

1. Слева внизу — **Project Settings** (шестерёнка) → **API**.
2. Скопируйте:
   - **Project URL** (например `https://xxxxx.supabase.co`)
   - **anon public** ключ (длинная строка в разделе Project API keys)
3. Откройте файл `config.js` и вставьте оба значения вместо плейсхолдеров:
   ```js
   const SUPABASE_URL = "https://xxxxx.supabase.co";
   const SUPABASE_ANON_KEY = "eyJhbGciOi...";
   ```
4. Сохраните файл. Демо-баннер на сайте пропадёт — теперь сайт работает
   с реальной базой.

## Шаг 5. Настроить подтверждение почты (для тестов)

По умолчанию Supabase требует подтверждения email при регистрации.
Для быстрого теста можно временно отключить это:

1. **Authentication** → **Providers** → **Email** → выключите
   **Confirm email** → Save.
2. Для реального запуска лучше, наоборот, оставить подтверждение включённым
   и настроить его (Authentication → Emails — можно использовать встроенную
   почту Supabase для старта, позже подключить свой SMTP, например через
   Resend или SendGrid).

## Шаг 6. Проверить, что всё работает

1. Откройте `index.html` в браузере (можно просто двойным кликом).
2. Зарегистрируйте тестового мастера («Ищу работу» → Регистрация → «Я мастер»),
   заполните профиль, загрузите пару фото.
3. Откройте это же в режиме инкогнито / другом браузере, зарегистрируйте
   тестовый салон, разместите вакансию.
4. Проверьте, что мастер виден салону, вакансия видна мастеру, отклик и
   приглашение работают.

## Шаг 7. Опубликовать сайт (деплой)

Сайт полностью статический (HTML/JS), сервер не нужен — подойдёт любой
бесплатный хостинг:

**Вариант А — Netlify (проще всего)**
1. Зайдите на netlify.com → зарегистрируйтесь.
2. На главной странице — перетащите папку с проектом (`index.html`,
   `app.js`, `config.js`) в область **Deploy** (drag & drop).
3. Через 10–20 секунд сайт будет доступен по ссылке вида
   `your-site.netlify.app`. Домен можно поменять в настройках сайта.

**Вариант Б — Vercel**
1. vercel.com → New Project → Deploy (можно тоже просто загрузить папку
   или подключить через GitHub).

**Свой домен:** в настройках Netlify/Vercel — Domain settings → Add custom
domain → следуйте инструкции по DNS (обычно 2 записи у регистратора домена).

## Обновление: модуль записи клиентов + чат + email (важно сделать один раз)

В проект добавлены: запись клиентов на услуги с депозитом, живой чат между
салоном и мастером, email-уведомления. Часть этого требует **повторно
запустить schema.sql** — в нём появились новые таблицы (`services`,
`salon_availability`, `bookings`) и новое поле в `vacancies`.

1. Supabase → **SQL Editor** → **New query**
2. Скопируйте **весь** обновлённый `schema.sql` (в нём есть `if not exists` /
   `on conflict do nothing`, поэтому старые таблицы он не тронет и не удалит
   ваши данные) → вставьте → **Run**
3. В **Table Editor** должны появиться новые таблицы: `services`,
   `salon_availability`, `bookings`

### Email-уведомления (необязательно, но включается за 5 минут)

Используется **EmailJS** — сервис, который отправляет письма прямо из
браузера, без своего сервера.

1. Зайдите на **emailjs.com** → зарегистрируйтесь бесплатно
2. **Email Services** → **Add New Service** → подключите свою почту (Gmail и
   похожие поддерживаются напрямую)
3. **Email Templates** → **Create New Template**. Внутри шаблона используйте
   переменные `{{to_email}}`, `{{subject}}`, `{{message}}` — например, тема
   письма: `{{subject}}`, тело: `{{message}}`
4. **Account** → скопируйте **Public Key**
5. В `config.js` вставьте три значения: `EMAILJS_PUBLIC_KEY`,
   `EMAILJS_SERVICE_ID` (из шага 2), `EMAILJS_TEMPLATE_ID` (из шага 3)

После этого письма будут уходить: салону — когда мастер откликнулся на
вакансию; мастеру — когда салон его пригласил; клиенту — когда он записался
на услугу. Если оставить плейсхолдеры как есть, сайт продолжит работать
как обычно, просто без писем.

### Про депозит 1000–1500 ₸ — важно понимать

Заявка на запись создаётся и хранится по-настоящему, сумма депозита
рассчитывается автоматически. Но **реального списания денег с карты нет** —
для этого нужен договор с платёжным провайдером (Kaspi Pay / Freedom Pay),
которого пока нет. Как только он появится — подключение займёт один день:
нужно будет добавить вызов их API в момент подтверждения записи
(`renderBookingWidget` в `app.js`).



- **Брендинг под клиента**: логотип, название, цвета (сейчас в `index.html`
  в `tailwind.config` — переменные `plum` и `peach`), домен под конкретный
  салон/сеть.
- **Приём оплаты за Premium-тариф**: для Казахстана — Kaspi Pay или Freedom
  Pay (интеграция через их API/виджет на странице `#/pricing`); для
  международных платежей — Stripe. Это отдельная небольшая доработка.
- **Модерация**: в Supabase можно добавить админ-панель (например через
  готовый интерфейс **Supabase Studio** — он уже встроен в дашборд) для
  проверки вакансий и профилей вручную.
- **Юридическое**: понадобится публичная оферта и политика обработки
  персональных данных (фото, контакты пользователей) — это не техническая,
  а юридическая часть, отдельно от кода.
- **Каждому клиенту — свой проект или мультитенантность**: либо создаёте
  отдельный Supabase-проект под каждый салон/сеть (проще, дороже в
  поддержке), либо дорабатываете схему под общую базу с разделением по
  `organization_id` (сложнее, но масштабируется). Для старта проще первый
  вариант.
- **Передача клиенту**: в Supabase можно добавить клиента как участника
  организации (Organization settings → Members) — тогда он получит доступ
  к своему проекту и данным напрямую.

## Ограничения текущей версии (что стоит знать)

- Дизайн-фреймворк — Tailwind CDN (Play CDN): отлично для демонстрации и
  быстрого старта, но для продакшена с высокой нагрузкой стоит собрать
  Tailwind локально (через npm) — это уменьшит вес страницы.
- Чат между мастером и салоном сделан в базовом виде (без обновления в
  реальном времени) — сообщения появляются после отправки, страницу можно
  обновить, чтобы увидеть новые. Реалтайм через Supabase Realtime
  добавляется буквально в несколько строк, если понадобится.
- Оплата Premium-тарифа сейчас не подключена технически (кнопка есть,
  списания нет) — see раздел про Kaspi/Stripe выше.

Если что-то не заработает на каком-то шаге — пришлите текст ошибки, разберём.
